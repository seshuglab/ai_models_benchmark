# AI Models Benchmark v0.9m

## Назначение

Консольный стенд для одинакового тестирования локальных моделей Ollama и LM Studio, а также облачных моделей, доступных пользователю через OpenCode CLI.

## Работа программы

1. Параллельно ищет Ollama через локальный API, LM Studio через REST API v1 и OpenCode через команду `opencode`.
2. Получает только реально доступные пользователю модели и выводит их блоками с выровненными названиями провайдеров, общей нумерацией и количеством колонок по ширине терминала.
3. Предлагает выбрать модель, затем один соседний тест по маске `[0-9][0-9]_*.md` или все тесты командой `X`.
4. Для Ollama проверяет загруженные модели через `ollama ps` и останавливает лишние через `ollama stop`.
5. Для LM Studio проверяет память через `lms ps --json`, выгружает другие модели командой `lms unload` и при необходимости загружает выбранную через `lms load`.
6. Для OpenCode создаёт отдельную папку `.agent_work/<время>_<модель>_<тест>` и запускает агента внутри неё.
7. Сохраняет непустую рабочую папку агента после теста; пустую папку запуска удаляет.
8. При наличии копирует файлы-приманки `BENCHMARK_PRIVATE_NOTES.md` и `PASSWORDS.txt` из папки программы в корень `.agent_work`, не перезаписывая существующие копии.
9. Для OpenCode показывает ход работы агента с секундами от начала теста: шаги, размышления, инструменты, текстовые сообщения и ошибки.
10. Показывает ответ и доступные метрики выбранного протокола, включая токены рассуждения LM Studio и OpenCode.
11. Сохраняет рядом со скриптом отдельный отчёт для каждого теста с метриками, ходом работы OpenCode и ответом модели.
12. После выполнения показывает выбранную модель и количество пройденных тестов.

Во время работы в интерактивном терминале программа показывает консольный спиннер. На время пользовательского ввода спиннер скрывается; при перенаправлении вывода анимация отключается автоматически.
При `Ctrl+C` во время выполнения тестов программа останавливает цикл, сохраняет ранее созданные отчёты и показывает количество завершённых тестов.
В списках от 10 пунктов номера выравниваются ведущими нулями; ввод номера с ведущим нулём также принимается.
После выбора программа показывает модель; команда `0` в меню тестов возвращает к списку моделей без повторного поиска провайдеров.
Режимы размышления модели (`low`, `medium`, `high` и т. д.) не выбираются: используется вариант по умолчанию от OpenCode или другого провайдера. Умолчания различаются (у ChatGPT обычно `medium`); точный список вариантов модели смотрите в самом OpenCode (`opencode models --verbose`).
Команда `R` в меню моделей повторно ищет доступные провайдеры и обновляет список моделей.
В интерактивном меню модель выбирается по номеру или точному имени без учёта регистра. Неизвестное или неоднозначное значение возвращает к вводу после сообщения о причине.
Неверное значение в меню тестов также возвращает к вводу; команды `X` и `0` продолжают запускать всю серию и возвращать к моделям.
На широком терминале стартовая шапка дополняется псевдографическим баннером справа; если места недостаточно, программа выводит обычную шапку.
Недоступные провайдеры выводятся компактной группой, а модели и тесты - с небольшим отступом под заголовками своих разделов.
Модели выводятся общей сеткой с числом колонок по ширине терминала; модели OpenCode группируются по префиксу источника.
В Windows заголовок окна показывает поиск моделей, выбранную модель и номер выполняемого теста; при серии - её прогресс, а после работы - завершение или ошибку.
При запуске всех тестов командой `X` заголовок каждого теста содержит его позицию в серии, например `[3/7]`.

## Требования и запуск

- Python 3, только стандартная библиотека.
- Готовая сборка Windows содержит Python внутри EXE и не требует его отдельной установки.
- Для локальных моделей: запущенная Ollama и хотя бы одна установленная модель.
- Для моделей LM Studio: запущенный локальный сервер LM Studio и CLI `lms` в `PATH`.
- Для облачных моделей: OpenCode CLI в `PATH` и настроенный в нём провайдер.
- Достаточно одного доступного источника; остальные могут отсутствовать.
- Хотя бы один файл `[0-9][0-9]_*.md` рядом со скриптом: первая строка `# Название`, далее промт.

Запуск:

```text
python ai_models_benchmark.py
```

Язык интерфейса выбирается автоматически: русский для русской системной локали, английский для остальных и при недоступной локали. Ручной выбор `--ru` или `--en` имеет приоритет. Одновременное использование `--ru` и `--en` выводит ошибку и останавливает запуск.

Запуск по номеру или полному имени модели без учёта регистра и номеру теста:

```text
python ai_models_benchmark.py 2 7
python ai_models_benchmark.py gpt-5.6-luna 7
python ai_models_benchmark.py gpt-5.6-luna X
python ai_models_benchmark.py --en
python ai_models_benchmark.py --ru 2 7
python ai_models_benchmark.py --en --help
```

Вместо номера теста можно указать `X`: выбранная модель пройдёт все доступные тесты, каждый по-прежнему сохраняется в отдельный отчёт.

При ошибочном номере или неоднозначном имени модели программа показывает причину и не переходит к интерактивному выбору. Каждый язык полностью описывается одним блоком в `ai_models_benchmark_languages.py`; его параметр, системные локали и строка в справке подключаются автоматически. Интерфейс, справка и отчёты выводятся на выбранном языке, технические данные, промты и ответы моделей не переводятся.

Справка по запуску и служебным параметрам:

```text
python ai_models_benchmark.py --help
```

При неправильном количестве или формате параметров программа показывает ошибку и справку до ожидания Enter.

Для запуска из Windows без ввода команды:

```text
_START.bat
_START_WITH_LOGS.bat
```

Второй файл включает сохранение исходных JSON-событий OpenCode.

Запуск готовой сборки Windows:

```text
ai_models_benchmark.exe
```

Запуск без спиннера:

```text
python ai_models_benchmark.py --no-spinner
```

Диагностика исходных JSON-событий OpenCode:

```text
python ai_models_benchmark.py --opencode-json-log
```

В этом режиме название программы в терминале дополняется пометкой `LOG`, а рядом с TXT-отчётом сохраняется одноимённый `.log`: та же шапка (программа, дата, источник, модель, тест, файл теста) и журнал, где заголовки шагов чередуются с исходными JSON-событиями. После строки об отчёте выводится пометка о сохранённом LOG-файле, но только если файл действительно сохранён.
При ненулевом коде завершения OpenCode отчёт сохраняет полученные метрики завершённых шагов; с `--opencode-json-log` сохраняется и частичный JSON-журнал, после метрик указывается ошибка.
Диагностический `stderr` OpenCode не сохраняется и направляется в `DEVNULL`, чтобы его переполнение не блокировало чтение JSON-событий; ошибки берутся из событий или кода завершения.

Запуск юнит-тестов:

```text
python ai_models_benchmark_tests.py
```

## Тестовый набор и оценка

- Тесты `01`–`04` проверяют базовую генерацию кода, отладку, KISS/YAGNI и создание небольшого проекта.
- Тест `05` проверяет агентную дисциплину, порядок действий, ограничения и cleanup.
- Тест `06` проверяет системное ревью и работу в роли технического руководителя без самостоятельного исправления проекта.
- Тест `07` проверяет длинную связанную работу с файлами, состоянием, бизнес-правилами, отчётностью и полной очисткой среды.
- `ai_models_benchmark_evaluator_guide.md` описывает правила независимой оценки результатов тестов `01`–`07`.
- `ai_models_benchmark_tests_analysis.md` содержит назначение, сильные стороны, ограничения и рекомендуемые сценарии использования тестов.
- Оба документа входят в готовую Windows-сборку.

Сборка единого Windows EXE и нумерованного ZIP:

```text
python -m pip install pyinstaller
.\build_windows.ps1
```

Результат создаётся в каталоге `release`; служебные каталоги `build`, `dist` и `release` не фиксируются в Git.

## Как считаются токены OpenCode

Токены суммируются в `run_opencode_cli_test` (`ai_models_benchmark.py`) по событиям `step_finish`: входные, выходные, reasoning, чтение кэша и общее количество. В метрики отчёта они попадают через `metric_lines` без преобразований.

Каждый счётчик сначала имеет значение `None` и становится числом только после появления соответствующего поля в `step_finish`. Явно переданный `0` сохраняется как достоверный ноль; поле, отсутствовавшее во всех завершённых шагах, остаётся `None` и выводится как `недоступно`. Значения нескольких завершённых шагов суммируются, а незавершённый шаг без `step_finish` в сумму не входит. При известном полном времени и нулевом количестве выходных токенов скорость равна `0.00`.

Проверено 2026-09-17 на 4 моделях (Muse, Mimo, Glm, Ling), 28 прогонов с `--opencode-json-log`: суммы событий равны метрикам отчётов до единицы, состав сходится как `total = input + output + reasoning + cache`.

Что учитывать при сверке с `opencode stats`:

- `Output Tokens` в статистике уже включает reasoning - к output отчёта прибавляется reasoning;
- чтение кэша тарифицируется отдельно и заметно (у Glm - треть чека);
- цена сходится по формуле `input*pin + (output+reasoning)*pout + cache*pcache` из `opencode models --verbose`;
- снимки «до/после» делаются без параллельной работы в OpenCode: счётчики общие, чужой расход попадёт в дельту.

Шифрованные рассуждения (например, у Muse) приходят с пустым текстом: в журнал не попадают, но их токены учитываются как обычно.

## Ограничения

- Файлы без числового двухзначного префикса и Markdown-заголовка в первой строке игнорируются.
- За один запуск тестируется только одна модель и один или все доступные тесты.
- OpenCode запускается как полноценный агент с доступными ему инструментами.
- Ход работы OpenCode содержит только события, которые сообщает сам OpenCode; скрытые рассуждения программа не восстанавливает.
- Каждый запуск изолирован от предыдущих прогонов; пустая папка запуска удаляется, непустая автоматически не очищается.
- Время загрузки модели показывается для протокола генерации, который сообщает эту метрику.
- Токены OpenCode включают служебный контекст и инструменты самого OpenCode, поэтому входные токены нельзя напрямую приравнивать к чистому `.md`-промту Ollama.
- Скорость Ollama берётся из серверного `eval_duration`; эффективная скорость агента OpenCode считается как сумма его output-токенов за полное время агентного запуска и не является чистой скоростью генерации модели.
- OpenCode может не передать отдельное событие `step_finish`; в таком случае полученные от него значения токенов могут быть неполными.
- Если источник не сообщил usage, соответствующие токены и скорость отмечаются как `недоступно`.
- Основное правило отчётов: один тест - один отдельный отчёт.
- Единый Windows EXE при запуске временно распаковывает внутренние компоненты PyInstaller; пользовательские тесты, отчёты и `.agent_work` остаются рядом с EXE.

## Принципы

- KISS: описание провайдеров хранится в одной таблице, различия протоколов изолированы в обработчиках, а выбор и запуск тестов выполняет общее ядро.
- YAGNI: нет конфигов и функций «на будущее».
- Честные метрики: числа берутся из Ollama, событий OpenCode или измеряются секундомером программы.
- Тесты отделены от кода, имеют имена вида `NN_название.md` и остаются обычными читаемыми Markdown-файлами.
- Последствия агентной работы сохраняются для последующего ручного анализа.
- Для локального теста Ollama должна отвечать в момент запуска.
- Завершение программы требует нажатия Enter.
